范围：把上一轮对标中列出的三个风险点与小瑕疵改掉，并实测。未改动官方材料、冻结契约（`docs/BUSINESS_CONTRACT.md`）、只读工具 I/O 与写入边界；未提交 Git。

## 一、规则变更现在真正生效（原第 1 风险）

### 问题

`RuleService` 把 R002=2.0、R003=1.0 写死，且与种子正文全等比较。导入/停用规则后：要么 `UNSUPPORTED_SCOPE`，要么新规则只入库不参与判定。评委现场"改规则看效果"会看到"规则不足"而不是行为改变。

### 改动

`src/main/java/com/taxagent/harness/tool/RuleService.java`

- 删除种子白名单 `OFFICIAL` 与 `officialDefinitions()`。
- 新增 `record PurposeRequirement(boolean everyInvoice, long thresholdCents)`，从**存储中的规则正文**解析两种官方表述：
  - 含「每张发票都必须填写用途」→ 每张必填；
  - 含「必须填写用途」+「大于或等于 X 元」→ 金额门槛（`BigDecimal` 转整数分，等于也必填）。
- 两种表述同时出现 → 视为矛盾，拒绝执行（不猜优先级）。
- 其余措辞 → `UNSUPPORTED_SCOPE`，保持 fail-closed。
- `checkInvoicePurpose` 改为按企业取唯一启用版本（多版本仍 `CONFLICT`，不发明优先级），用解析出的语义判定，并返回**实际生效版本**的引用。
- `requireSupportedWriteRules` 不再要求"所有启用规则都与官方一致"，只要求用途规则存在且语义可执行；9 月范围限制不变。

### 验证

单元测试（`RuleServiceTest`，新增 2 项，共 11 项通过）：

| 场景 | 结果 |
|---|---|
| 停用 R002 2.0 + 导入 R002 3.0（≥1000.00 元必填，生效 2026-09-01） | 缺用途只剩 F006；引用 `R002@3.0` |
| 再停用 3.0 + 导入 3.1（每张必填） | 恢复 5 张；引用 `R002@3.1` |
| 正文改成「所有发票不必填用途」/无法解析 | 仍 `UNSUPPORTED_SCOPE`（原测试保持通过） |
| 正文同时写"每张必填"和"≥1000 元必填" | `UNSUPPORTED_SCOPE`（新增测试） |

真实服务验证（副本库 `/tmp/rulecheck/demo.db`，端口 18087，`qwen3.7-flash`）：

- CLI：`--rules-disable R002 2.0` → `DISABLED`；`--rules-import R002 3.0` → `IMPORTED`；`--rules-list --date=2026-09-15` 只剩 R002 3.0。
- 模型一轮（10.5s）：调用 `check_invoice_purpose`，返回 `missing=['F006']`、`rules=[R002@3.0]`；模型回答「缺 F006，依据 R002 第 3.0 版」。
- 数字口径：本节的 1 张 / 5 张都取自**副本库的干净基线**（`/tmp/rulecheck/demo.db`，全程无写入），与新建库口径一致；`TEST_REPORT` 中的 4 张 / 3 张属于另一个已写入过的库，不可与本表混用。

## 二、运行记录持久化（原第 3 风险）

### 改动

- `DemoAudit`：新增 append-only 表 `agent_trace`（用户、企业、requestId、taskId、system prompt、完整用户消息、工具名、历史条数、memorySource、outcome、时间），带禁 UPDATE/DELETE 触发器；新增 `appendTrace` 与 `traces`。
- `DemoController`：每轮结束写入 trace（含失败轮），新增 `GET /api/demo/tasks/{id}/traces`（按用户/企业校验，最多 5 条）。
- 前端：检查器"完整模型输入"在页面刷新/进程重启后回退到持久化记录；`api.ts` 新增 `SavedTrace` 与 `traces()`。

## 三、模型把 `finish` 当工具调用导致整轮失败（实测新发现）

真实模型在 18087 上把结束协议发成 `tool_calls: finish`，运行时按未知工具返回 `INVALID_ARGUMENT`，工具结果虽已算出但整轮报错。

改动 `AgentRuntime`：单个 `finish`/`ask` 伪工具调用按文本协议归一化（读 `text` 或 `content`，长度 ≤4000），仍遵守"有工具错误不得报成功"和"批准轮未核验不得结束"；其他未知工具照旧拒绝。新增 2 项测试（共 27 项通过）。
