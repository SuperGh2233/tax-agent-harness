# REQ/PLAN: T04 工具 Schema、错误码与权限校验

状态：completed；完成日期：2026-10-30。

## 问题与目标

T05 及后续工具需要共用、可检查的参数和结果约定，并在任何业务读取或写入前执行确定性权限校验。T04 将这些边界固定下来，避免模型输入决定用户身份、企业权限或可写字段。

## 范围

- 为发票查询、流水查询、用途检查、发票更新、任务/记忆状态及规则管理定义模型可提交的输入 Schema 和不可变 Java DTO。
- 定义稳定错误码、错误响应形状和严格 JSON 解码。
- 基于 T03 的权限表实现读取/写入访问检查，并覆盖官方 U001/U002 权限矩阵。
- 提供自动化契约与权限测试。

## 非目标

不实现财务查询（T05）、规则匹配/用途计算（T06）、供应商 Tool Calling（T07）、任务/记忆持久化（T08）或发票实际写入、授权绑定、幂等和保存后回读（T09）。不新增 HTTP 认证入口，不更改官方材料、冻结业务契约、T03 schema、种子或数据库。

## 约束与契约

唯一业务依据为 [冻结业务契约](../BUSINESS_CONTRACT.md)。U001 对 C001/C002 均可查看并修改；U002 对 C001 仅可查看，对 C002 无权访问。规则管理角色尚未在官方材料中定义，因此管理写操作默认拒绝。用户身份由可信调用方单独提供，不属于模型工具 JSON。发票更新字段仅限 purpose、remarks；不推断官方未规定的字段长度或规则。

完整机器契约见 [工具 SPEC](../../specs/TOOL_CONTRACT.md) 和 `src/main/resources/tool-contract.schema.json`。

## 实现步骤

1. 固定输入/输出、错误码、身份与权限边界。
2. 实现严格解析、不可变 DTO 和参数化 SQL 权限守卫。
3. 用 JUnit 验证 JSON Schema 与 DTO 一致、额外字段拒绝、权限矩阵和故障分类。
4. 使用 JDK 21 运行完整 Maven 测试，并记录实际结果。

## 风险与回退

本任务不改变数据库结构，也不写入业务数据库。若契约或实现需回退，只移除 T04 新增的工具契约、权限守卫、schema 和测试，并恢复关联文档；保留既有 T00–T03 工作及数据。

## 验收标准

- 查询、写入、规则和任务工具输入均有可检查 Schema 与可测试 DTO；额外属性、类型错误及非法组合被拒绝。
- 权限校验逐次读取 T03 权限表，缺身份/未知主体/无权企业/只读写入均返回稳定错误。
- 六项官方权限组合与白名单、错误 envelope 有测试覆盖。
- JDK 21 下完整 Maven 测试通过；未实现 T05 及之后的业务执行器。
