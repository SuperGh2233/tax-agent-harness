## 目标与基线

在 T10 已通过的三类官方场景上补足回归与故障注入证据，确保权限、企业隔离、规则选择、重试/超时和“空结果与失败”边界不回归。T10 的基线是 JDK 21 离线 Maven 全量 158/0/0/0；其集成测试已覆盖正常写入、事务回滚、同 operationId 幂等和 recover，但尚未覆盖“财务写入已提交、随后 TaskMemory 状态保存失败”。

## 覆盖范围

1. **权限拒绝**：按冻结契约验证 U002 对 C001 只读、对 C002 无权；写入或无权访问必须返回权限错误，不能伪装为空结果或成功。
2. **跨企业隔离**：验证用户/任务/记忆归属保持用户与企业边界；发票、流水按复合键定位，企业切换后不能读取或恢复另一企业的数据。
3. **规则版本**：验证 2026-09 的 C001 仅使用生效的 R002 2.0，不回退到已停用的 1.0；C002 使用 R003 1.0。规则缺失、停用或版本冲突按既有契约报错，不推断优先级。
4. **重试与超时**：核对模型有限重试配置及工具不自动重试；写入结果不确定时先调用只读 recover 和新鲜回读，不盲目重放。通过调用/台账计数确认没有重复写入。
5. **空结果与失败**：成功查询无记录返回空集合及 0；权限、SQLite 或运行时故障必须保留错误，不能降级为空结果。
6. **关键提交边界故障注入**：使用隔离的临时 SQLite 数据库，先记录任务状态和版本；在 TaskMemory 持久化更新处注入 SQLite 失败，再经 FinanceAgent 的可信明确授权路径执行一次发票更新。验证业务发票和 invoice_operations 台账已提交且各只有一条有效操作；任务状态保存错误被报告、任务状态/版本未被误报为完成；随后 recover(operationId, update) 与新鲜查询能确认实际已保存值，不再调用写工具、不自动重放。测试需以真实代码与现有表结构确认注入点，避免依赖运行数据库或不稳定的全局状态。
