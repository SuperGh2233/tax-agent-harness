## 继续有效的初赛条款

以下约束复赛不变，新功能必须同样遵守：

1. **写入边界**：发票只允许修改用途、备注；银行记录只读；不执行真实记账、付款、报税。复赛要求没有放宽这一点。上传文件导入的是新记录，不是修改已有记录的通道（见 B2）。
2. **模型与程序分工**：模型负责理解与决策；程序负责金额计算、参数检查、权限检查、保存和回读。不能用关键词或固定分支冒充模型决策。
3. **写入证据**：用户明确要求、可信批准、一次性授权、操作号幂等、事务回读；没有本轮核验结果不得报告保存成功。（复赛“异常恢复”：已完成操作不重做、待确认操作不擅自执行。）
4. **身份**：用户、企业身份来自可信会话或配置，绝不来自对话文本或模型参数。
5. **金额口径**：整数分计算；发票合计与银行收入、支出分别统计；银行记录不能证明某张发票已付款（R001、R004）。
6. **运行安全**：仅 loopback；密钥只经环境变量；运行记录不含密钥；审计 append-only 且脱敏。
7. **Git**：不擅自 `git add` / `commit` / `push`。

## 复赛新增约束

| 编号 | 约束 | 复赛依据 |
|---|---|---|
| B1 | **文件来源与版本**：每个上传文件记录上传者、企业、时间、内容哈希和版本。内容哈希相同的重复上传不产生新数据；同名不同内容为新版本，旧版本保留可追溯。 | 二“文件处理”：来源、版本、防重 |
| B2 | **防越权覆盖**：上传只能写入上传者有修改权限的企业。导入时已存在的业务记录（同企业＋同编号）不被覆盖，作为冲突逐条报告。是否允许经确认后覆盖，见“待确认”第 2 条。 | 二“文件处理”：防越权覆盖 |
| B3 | **依据定位**：从文件得出的金额与答复须能指向文件、版本及位置（工作表/单元格或段落/页）。 | 二“文件处理”：依据定位；“知识库策略”：溯源 |
| B4 | **Agent 配置生效范围**：配置变更只对变更后开始的轮次生效，进行中的轮次不受影响。Agent 的有效权限为“当前用户权限 ∩ Agent 能力权限”，配置不能扩大用户权限。 | 二“Agent 管理” |
| B5 | **能力停用**：停用的 Tool、Skill 或知识资料不发给模型；模型仍调用时拒绝，并给出明确错误码，不静默忽略。 | 二“能力组织与复用” |
| B6 | **记忆生命周期**：新旧要求冲突时，以用户最新明确陈述覆盖，旧值不再进入模型输入；删除或失效的记忆从存储与模型输入中彻底清除，审计只保留脱敏元数据。个人记忆与企业记忆分开存放、分开授权。 | 二“长期记忆” |
| B7 | **上下文回溯**：压缩后的模型输入必须保留任务对象、用户限制和待办；被裁剪的原文（对话、文件片段、工具结果）可经只读工具按需取回。 | 二“上下文管理” |
| B8 | **交付文档**：提交包根目录放 `作品使用说明.md`（启动、在哪里配置 Agent/能力、上传文件、发起对话、查看业务数据变化、执行记录和模型输入）；参与创新项时放 `自主创新说明.md`（同模型同任务的前后对比）。 | 五 |

## 待确认

1. 复赛截止时间、提交入口、包大小与文件大小上限：**仍未知**，以主办方通知为准，不得自行推定。

4. 上传的 Word/PDF **只作检索知识**；可执行规则仍须经规则导入，按 A2/A3 解析。
