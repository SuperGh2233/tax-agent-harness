# 审计保留策略

## 设计决定

`demo_audit` 是**只追加**审计流：

- 数据库触发器禁止 `UPDATE`、`DELETE` 和 `INSERT OR REPLACE`，应用没有删除入口。
- UI 只读取当前用户/企业的最近记录；导出 CSV 通过受保护的 `/api/demo/audit/export` 完成。
- 审计记录不保存 API Key、完整模型输入中的业务明细不应写入日志；模型输入 trace 通过接口返回，不写入审计。

这是有意的安全边界：为了“可证明未发生未核验写入”，系统不接受事后改写或选择性删除审计。

## 保留周期

- 演示实例：审计与演示数据库同生命周期；演示结束前由操作者导出 CSV，随后整库归档或删除。
- 不提供自动清理/滚动删除。若部署到真实环境，应由外部归档系统按组织保留周期处理：先导出并校验 CSV，再在应用之外归档/删除整个数据库；不得在应用内删除单条审计。
- 导出文件是敏感运行记录，按最小权限保管；不得包含密钥、真实财务数据或个人信息。

## 验证

- `DemoAudit` 创建 `demo_audit_no_update`、`demo_audit_no_replace`、`demo_audit_no_delete` 触发器。
- 导出由 `DemoController` 的审计导出端点完成，CSV 仅含已脱敏字段（用户/企业、turn、工具、结果、规则版本、记忆来源、耗时）。
- 关闭/归档前的检查见 `RELEASE_CHECKLIST.md`；运行证据见 `docs/evidence/REAL_E2E_20261106.md`。
